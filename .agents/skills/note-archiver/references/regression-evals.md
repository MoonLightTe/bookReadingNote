# 归档技能演进评估与回归测试规范 (Regression & Evals)

> 本规范用于检验 `note-archiver` 是否在迭代中出现倒退（如破坏心流、误判污染、重复归档导致内容重复等）。

---

## 1. 黄金回归测试集 (Golden Test Cases)

| 用例编号 | 测试场景 | 输入特征 | 预期断言 (Pass Criteria) |
| :---: | :--- | :--- | :--- |
| **TC-01** | **快速心流模式** | 读者明确要求“快速归档”或参数 `--quick`，草稿含大量随手疑问 | **NEVER** 强制打断读者开启答辩；静默落库草稿，在报告中将疑问列为 `proposed` 待后续探讨，`reading/` 清空。 |
| **TC-02** | **深度研讨模式** | 读者要求“归档并回答问题加讨论”或 `--deep` | 优先正面剖析疑问，**标注依据类型（原文/AI推演/读者洞察）**；将讨论精华沉淀至章节专属 `Socratic Q&A Log`；不产生空泛废话。 |
| **TC-03** | **纯文本/纯摘抄草稿** | 草稿中仅有原文段落，无疑问、无图片 | 正常归档至书籍目录，**不强行无中生有**捏造 Q&A，不产生虚假金句。 |
| **TC-04** | **多媒体图片混排** | 草稿中包含本地 `image.png` 引用 | 图片自动移入 `books/.../assets/chXX-xxx.png`，正文 Markdown 引用路径自动改写为本地相对路径，原图不丢失。 |
| **TC-05** | **重复触发幂等性** | 对同一章节草稿重复执行归档 | **幂等不重复**：不产生重复的 Q&A 编号，不覆盖已有的深入研讨内容，不复制重复的图片。 |
| **TC-06** | **跨书概念冲突** | 新书观点与已有书籍严重冲突（如集中式架构 vs 分布式架构） | **保留争议**：生成 `CONFLICT-xxx` 冲突卡，不强行抹平矛盾，留待主题研讨。 |

## 2. 核心人工评估指标 (Human Eval Rubric)

每次评估 Skill 输出时，基于以下 4 个维度打分（1~5 分）：

1. **心流保护度 (Flow Preservation)**：是否在不需要的时候打断了读者的思维？是否把读者逼成了“答辩模式”？
2. **解惑穿透力 (Insight Depth)**：AI 的回答是否立足第一性原理？是否明确标注了是“书内事实”还是“AI 外部推演”？
3. **资产可召回度 (Retrievability)**：产出的金句、任务、Q&A 是否具备稳定 ID、场景标签与明确状态？
4. **知识库纯度 (Library Hygiene)**：是否产生重复条目、伪金句、或是形式主义打卡任务？
