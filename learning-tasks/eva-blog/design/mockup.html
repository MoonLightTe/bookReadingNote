暗色模式不闪烁：

深色模式最常见的毛病是刷新时「白一下」：页面已经按浅色画出来了，主题脚本才姗姗来迟。问题不在浏览器，而在执行顺序。

闪烁从哪来

主题脚本通常放在 body 末尾，或者打成独立文件。浏览器执行到它之前，并不知道该用哪套颜色，于是先用默认的浅色画一帧，脚本跑完再换成深色。这一帧就是闪烁。

内联脚本

把读取偏好的逻辑直接写进 head，在首次绘制之前给根元素打上标记：

is:inline 是关键：它让 Astro 原样输出这段脚本，而不是打包成外部文件。

WARNING内联脚本里不要引用外部文件，也不要等 DOMContentLoaded，否则又会多出一次等待。

怎么验证

  • 打开开发者工具的 Rendering 面板，把 prefers-color-scheme 设为 dark 后强制刷新。
  • 在 Network 面板勾选 Disable cache，观察首帧是否已经是深色。
  • 切到慢速网络再试一次：内联脚本不依赖网络，结果应当不变。

小结

一共三行：读偏好、写标记、放进 head。颜色本身交给 CSS 变量接管，下一话讲怎么把它们收进 Design Token。

05

公式

实现：remark-math 解析，rehype-katex 在构建期渲染成 HTML，页面不加载公式脚本。编号面板是包在外面的 figure。视觉稿用浏览器原生 MathML 离线示意，真实字形以 KaTeX 为准。

行内公式嵌在句子里，例如质能方程 E=mc2，字号跟随正文。

写错的公式不会被吞掉：KaTeX 会把源码原样输出，这里给它配上红色标签。

08

脚注、分割线与折叠

实现：脚注由 GFM 内置，写 [^1] 即可。分割线渲染成黄黑警示条。折叠块用原生 details 元素，不需要脚本。

Astro 7 的默认处理器是 Sätteri1，本站为了公式和流程图切回了 Unified2。

展开：为什么不用默认处理器

因为 Sätteri 不能直接使用 remark / rehype 插件，而公式、提示框、上下标这些能力都来自那个生态。

NOTES注释

  1. 自 Astro 7 起，Sätteri 是默认的 Markdown 处理器。↩
  2. 通过 markdown.processor = unified() 切换。↩
