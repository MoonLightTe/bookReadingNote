# 决策裁决 (Deciding & Action)

> 本模块用于选项分歧、犹豫不决、排定优先级或破解拖延。


## 双向钢人论证 (`steelman-both-sides`)
**定位**：两个选项都有道理的时候，把两边都论证到最强

```markdown
我需要做的决定是：【写清问题、两个选项、目标和现实约束】。

先别急着回答，也别默认我已经把问题想清楚。请先做一次双向钢人论证：

1. 用最完整、有力的方式，重述我真正需要做出的选择；
2. 分别给出支持两个方向的最强理由、适用条件、最大收益、最大风险，以及最难回答的反对意见；
3. 找出双方真正的分歧、最可能改变结论的关键变量，以及还需要补充的信息；
4. 只问我一个最可能改变结论的问题。

等我回答以后，再给出明确判断、理由、适用条件和下一步行动。
```

## 最小实验 (`minimum-experiment`)
**定位**：别再推演了，花七天真跑一次，让现实给你数据

```markdown
我正在纠结的是：【填写你的选择或想法】。

请先找出这个决定背后最需要验证的3个假设，再选出最可能改变最终结论的那一个。

围绕这个假设，帮我设计一个低成本、可逆、能在【7天或你能接受的周期】内完成的最小实验。

请写清：
1. 具体要做什么；
2. 需要投入多少时间和资源；
3. 观察什么指标；
4. 什么结果支持继续；
5. 什么结果提醒我停止；
6. 实验结束后能获得什么新信息。

最后告诉我，明天就能开始的第一个动作是什么。
```

## 机会成本与可逆性 (`opportunity-cost`)
**定位**：每件事先问放弃什么、能不能退回来、不做会怎样，再排先后

```markdown
我现在面对的选择是：【写下你在纠结的事，可以是「做还是不做」，也可以是一串不知道先做哪件的事】。
我手上的约束是：【时间、钱、精力、人手，哪样最紧就写哪样】。

请帮我用机会成本和可逆性把这些事过一遍，排出先后。

第一步，把每个选项（包括「什么都不做」）单独列出来。每一项回答三个问题：
1. 做了它，我要放弃什么？写具体的东西，比如「这周不能写方案了」，不要写「会占用时间」。
2. 做错了能不能退回来？能低成本退回来的算双向门，退不回来或者退回来很贵的算单向门。说清楚退回来要花什么。
3. 不做它，接下来一个月会发生什么？会不会有东西变坏、有机会关上？还是其实什么都不会发生。

第二步，按下面的规矩给每一项定节奏：
- 双向门：信息够七成就定，别再开会讨论，先做了再说。
- 单向门：放慢，先列出还缺哪几条信息，补齐再定。
- 不做也没什么后果的：直接划掉，或者放进以后再说的清单。

第三步，排出先后顺序，说明排序靠的是哪一条理由。

最后请输出：
1. 一张表：选项、放弃什么、双向门还是单向门、不做的后果、节奏；
2. 排好的先后顺序，第一件写清楚今天就能开始的那个动作；
3. 这次我最可能高估的一件事和最可能低估的一件事。
```

## 执行意图 (`implementation-intention`)
**定位**：事情已经定了却开不了头，写成如果碰到什么、我就做什么

```markdown
我已经决定要做的事是：【你知道该做、却一直没开始的那件事】。
我希望它变成的样子是：【一句话写下你真正想要的结果】。

请帮我用 WOOP 和执行意图，把这件事变成今天就能照着做的计划。

第一步，按这个顺序问我。一次只问一个，等我答完再问下一个：
1. 愿望：这件事做成，我具体想要什么。
2. 最好的结果：最好的那种结果发生时，我看到什么、感觉到什么。请我在脑子里把那个画面过一遍，再说出来。
3. 内在障碍：我自己这边，最可能让我开不了头的那一个障碍。要内在的，比如「一坐下就想刷手机」「觉得还没准备好」。我说的是别人不配合、环境不允许，请再问一次，直到问到我自己身上的那一个。
4. 计划：碰上这个障碍时，我可以做的一个很小的动作。

第二步，把上面的内容收成 1 到 3 句执行意图。句式固定成：
如果「具体的情境、时间或地点」，那么我就「一个小到马上能做的动作」。
其中必须有一句是专门对付刚才那个内在障碍的。情境要具体到能被碰到，比如「今晚九点坐到书桌前」，不要写「有空的时候」。动作要具体到不用再想一步，比如「打开文档写下标题」，不要写「开始努力」。

最后请输出：
1. 那 1 到 3 句如果那么，每句单独一行，今天就能照着做；
2. 标出哪一句是对付内在障碍的。
```

## 外视角与基准比率 (`outside-view`) [新增法宝]
**定位**：预估工期、评估技术重构难度或做重大规划时，强制调取历史统计基准比率，打碎过度自信。

```markdown
# Role: 外视角冷酷校准官 (Outside View & Base Rate Calibrator)
核心法则：打破规划谬误（Planning Fallacy）。你在内部看到的所有“信心、优势与乐观排期”，在统计学的大数定律面前都是错觉。

请按以下三步执行冷酷校准：
1. 寻找统计参考类 (Reference Class)：
   - 剥离“我们这次不同”、“我们用了新技术”等主观叙事，在工程与历史上找到同等量级、同等复杂度的真实案例库。
2. 调取基准比率 (Base Rate)：
   - 这类项目的历史平均耗时是预估的多少倍？（软件工程行业均值：中大型重构平均超期 2.0~3.0 倍）。
   - 历史上类似决策或项目的失败/回滚率是多少？
3. 设立保守交付基线与熔断线：
   - 依据基准比率重构里程碑与资源预算；
   - 设定“单向门”检查点：如果投入超过基准比率的 1.5 倍仍未完成，必须执行止损或降级。
```
